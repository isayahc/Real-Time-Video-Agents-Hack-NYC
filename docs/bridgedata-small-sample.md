## Bounded acquisition

```powershell
python -m scripts.sample_bridgedata --count 10 --output data/bridgedata-v2-sample-10
```

Only the first ten trajectory-index rows from the publisher's website were selected.
Individual primary-camera JPEG URLs were fetched; **no dataset archive, training
shard or full repository was downloaded**. The script allows only 10 or 20 episodes,
caps each trajectory at 300 frames, each JPEG at 3 MiB and total frame downloads at
100 MiB. Existing output directories are refused. Partial evidence survives failure.

Actual acquisition: **10 trajectories, 302 JPEG frames, 35,647,584 downloaded frame
bytes (34.0 MiB)**. Ten locally encoded MP4s add **4,606,699 bytes**. Files remain
under ignored `data/`; source URLs, per-frame/video SHA-256 hashes, attribution and
modification notes are in `manifest.json` there.

## Derived input and selected run

Original JPEG bytes are unchanged. Each MP4 is H.264/yuv420p encoded at **5 fps**, based
on the publisher's reported control frequency. Original capture timestamps are not
available in this download; the derived timeline is not a measured motion duration.
No annotation text, labels or overlays are burned into the input.

Selected `episode-01/source.mp4`: 28 frames, 5.6 seconds, 474,648 bytes.
SHA-256: `dfa513a45d7e9af603beafb1b083b2b5a3ba9af8aebb4e32fa43d20bf1018420`.
First/last-frame inspection shows a toy mushroom moving from the tabletop into
a metal pot. This observation is not supplied as a ground-truth answer to the model.

The user's previously approved **one paid E2E invocation** applies to this permitted
replacement input: Nebius Nemotron vision, GMI GPT-6 Astra reasoning/CAD, one visual
review pass and existing bounded retries. No paid batch across the ten examples.

```powershell
python scripts/run_e2e.py --video data/bridgedata-v2-sample-10/episode-01/source.mp4 --config examples/e2e/config.json --visual-passes 1
```

index reads after ten rows, path validation and excessive-frame rejection.
